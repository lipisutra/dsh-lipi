# Правила исполнителя пакета dsh-lipi

Для того, кто меняет код бандла: инструменты, виджет, скилл, тесты и выпуск.
Документация и рабочие материалы ведутся по [правилам lipi](lipi/README.md) — эта
страница про сам пакет.

## Тесты <a id="tests"></a>

```bash
npm test
```

Запускает `node --test test/*.test.mjs` (вариант `node --test test/` с каталогом
на Node 22 падает — тесты перечисляются маской). Перед коммитом тесты зелёные.

## Синхронизация справочников скилла <a id="vendor"></a>

Справочники скилла — копии текстов установленного lipi: все языковые редакции
`share/lipi/docs/<язык>/*` попадают в `skills/lipi/references/<язык>/*`, а
`share/lipi/SETUP.md` — в `skills/lipi/references/setup.md`. Каталоги редакций
обходятся без зашитого списка языков: сколько каталогов `docs/<код>/` есть в
пакете, столько копий и появится. Обновляет их:

```bash
node scripts/vendor.mjs
```

Скрипт находит установленную команду `lipi` (`LIPI_BIN` или PATH), по её
shebang определяет Python и через `sysconfig` берёт data-каталог; версию
читает из `lipi --version`. При `lipi < min` из `package.json` (сейчас
`1.0.0`) завершается с кодом 1, ничего не копируя; при успехе обновляет
копии, печатает, что откуда взято, удаляет устаревшие файлы и пишет
`skills/lipi/references/version.json` (`{"lipi": "<версия>", "min": "<минимум>"}`).
Если установленный пакет не поставляет `share/lipi` (editable-установка),
редакции берутся с тега выпуска `v<первая цифра версии>` репозитория
`lipisutra/lipi` через git (запасной путь загрузки одной страницы — raw);
при недоступности сети — понятное сообщение и код 1. Тест
`test/vendor.test.mjs` сверяет проданные копии с установленным пакетом и
пропускается, когда `share/lipi` недоступен.

## Коммиты <a id="commits"></a>

Сообщение коммита пишется на английском. Оно упоминает ID работы, которую
двигает (например, PLN-003) — по нему аудит A5 сверяет статус работы с
историей git.

## Выпуск пакета <a id="release"></a>

1. Поднять `version` в `package.json` и дополнить `CHANGELOG.md` записью о
   выпуске.
2. Коммит «Bundle X.Y.Z: <what changed>» в `master` и пуш.
3. Аннотированный тег `vX.Y.Z`; для старшей линии (`v1`) передвинуть указатель
   `v1` на тот же коммит.

## Проверки перед коммитом <a id="checks"></a>

```bash
npm test
lipi check
lipi audit
```

Ошибки исправляются до коммита; на каждое предупреждение аудита нужен ответ:
исправлено или не требуется, и почему.
