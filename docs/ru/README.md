# dsh-lipi

<p align="center"><img src="../assets/logo.png" alt="LipiSutra" width="360"></p>

<p align="center">Бандл DeepSeek Harness для проектов по lipi.</p>

Нативный бандл DeepSeek Harness для проектов, которые ведутся по lipi. Даёт
агенту срез по задаче, карту покрытия, проверку документации и создание
рабочих документов; проверки запускает установленная команда `lipi`, бандл не
меняет ни её, ни проект. Карточка бандла — [DETAIL.md](DETAIL.md).

lipi — инструмент ведения документации проекта: разворачивает правила
исполнителя (`AGENTS.md`, `.agents/lipi/`), описание (`docs/`) и рабочие
материалы (`workflow/`). Проверяет проект установленная команда `lipi check`:
она находит битые ссылки, нарушения размеров и шапок документов, устаревший
указатель и расхождение описания с кодом. Бандл не ищет в проекте чекер:
проект считается развёрнутым, если в его корне есть `lipi.json`.

## Что добавляет бандл <a id="parts"></a>

| Что | Где |
| --- | --- |
| Инструменты агента | `lipi_check` — запускает установленную команду `lipi check` в проекте в режимах `quick`, `staged`, `audit`; `lipi_slice` — срез карты знаний проекта по цели (разделу, странице, файлу кода или номеру работы) или по изменениям (`--diff`, `--staged`); `lipi_map` — карта покрытия: цели описания, слои кода и тесты с числом мест; `lipi_graph` — граф связей проекта: impact-подграф по узлу, сироты, явные якоря без `@trace`, цепочка устаревания по staged/diff, фильтр по типам, экспорт mermaid/dot; `lipi_new` — планы, замечания, решения и другие рабочие документы через `lipi new` |
| Команды хоста | `/lipi-check`, `/lipi-slice`, `/lipi-init`, `/lipi-doctor`, `/lipi-map` и `/lipi-lang` — те же действия из чата; `/lipi-lang` без аргумента показывает язык интерфейса, с кодом (`/lipi-lang ru`) переключает его |
| Карточки в чате | Результаты `lipi_check`, `lipi_slice`, `lipi_new`, `lipi_map` и `lipi_graph` — карточками через слот `tool.call.toolview`: бейдж статуса, кликабельные пути к файлам, блоки среза, строки карты; нераспознанный вывод остаётся текстом |
| Виджет в доке | Компактная иконка с индикатором состояния (зелёный — чисто, жёлтый — предупреждения, красный — ошибки) и выпадашкой: сводка, запуск `quick`/`staged`/`audit`, срез по цели (`lipi slice`), карта покрытия (`lipi map`), развёртывание `lipi init` в папке без каркаса, диагностика `lipi doctor`, переключатель языка, список находок |
| Язык | Язык интерфейса и карточек — язык lipi: сейчас `en` и `ru`, другие берутся из каталога переводов установленного пакета и не требуют правок бандла. Справочники скилла есть для каждой языковой редакции описания |
| Скилл | `skills/lipi/SKILL.md` — когда проверять, как развернуть, как начать задачу со среза |
| Справочники скилла | `skills/lipi/references/<язык>/*` — копии всех редакций описания lipi; `setup.md` — инструкция развёртывания; `version.json` — версия lipi и минимум |
| Синхронизация текстов | `scripts/vendor.mjs` — сверяет совместимость с lipi и обновляет копии всех редакций |

## С чего начать <a id="start"></a>

1. Установите lipi на машину (нужен Python 3.9+):

   ```bash
   pipx install git+https://github.com/lipisutra/lipi
   lipi --version
   ```

   Обновление — `pipx upgrade lipi`. На Windows lipi может работать через WSL;
   для проектов по пути `\\wsl.localhost\...` команда запускается внутри WSL,
   дистрибутив задаёт ключ `wslDistro`.
2. Добавьте пакет `@lipisutra/dsh-lipi` в профиль DeepSeek Harness и включите
   бандл в Plugin Manager. Локальный бандл из каталога WSL установить нельзя
   (Windows не умеет ссылаться на `\\wsl.localhost\...`), поэтому скопируйте
   пакет на локальный диск, например `C:\Users\<имя>\projects\lipi-dsh`, и
   укажите Plugin Manager эту копию; источник остаётся в WSL.
3. Убедитесь, что проект развёрнут по lipi: в его корне есть `lipi.json` (его
   создаёт `lipi init`); рядом лежит `.agents/lipi/lipi.lock` с версией
   развёртывания. Если каркаса нет — `lipi init` для нового или существующего
   проекта.
4. Попросите агента «проверь документацию по lipi», вызовите `/lipi-check` или
   инструмент `lipi_check`.

Если PATH не видит команду `lipi`, укажите путь к ней в ключе `lipiPath`.
Node.js нужен только для `scripts/vendor.mjs`.

## Настройка <a id="config"></a>

Ключи конфигурации бандла и значения по умолчанию:

| Ключ | По умолчанию | Что задаёт |
| --- | --- | --- |
| `lipiPath` | пусто | Путь к установленной команде lipi; пусто — команда `lipi` из PATH. |
| `wslDistro` | `Ubuntu` | Дистрибутив WSL, внутри которого запускается установленный lipi, когда проект открыт по пути `\\wsl.localhost\...` на Windows. |
| `maxItems` | `50` | Предел числа ошибок и отдельно предупреждений в выдаче `lipi_check`. |
| `maxNodes` | `200` | Предел числа узлов в выдаче `lipi_graph`. |
| `maxEdges` | `400` | Предел числа рёбер в выдаче `lipi_graph`. |

Для проекта, открытого через WSL, `lipiPath` — путь к команде внутри
дистрибутива; пусто — `lipi` из PATH этого дистрибутива.

## Версии и синхронизация текстов <a id="versions"></a>

Версия пакета независима от версии lipi. Пакет объявляет минимальную
совместимую версию в `package.json` (`"lipi": {"min": "1.0.0"}`) и при проверке
проекта сравнивает её с версией установленного lipi из JSON-вывода
`lipi check`: если она старше минимума, результат несёт подсказку обновить
lipi. Справочники скилла — копии текстов установленного пакета lipi:
редакции описания из `share/lipi/docs/<язык>/*` (какие каталоги есть, столько
и копируется — список языков не зашит) и `share/lipi/SETUP.md`. Если
установленный пакет не поставляет `share/lipi` (editable-установка), они
берутся с тега выпуска `v<первая цифра версии>` (`lipisutra/lipi`). В
репозитории копии обновляет

```bash
node scripts/vendor.mjs
```

Скрипт находит установленную команду lipi (`LIPI_BIN` или PATH), по её shebang
определяет Python и через `sysconfig` берёт data-каталог, версию читает из
`lipi --version`; при `lipi < lipi.min` завершается с кодом 1, ничего не
копируя. При успехе он обновляет копии и `skills/lipi/references/version.json`
(`{"lipi": "<версия>", "min": "1.0.0"}`) и удаляет устаревшие файлы прежней
раскладки. Тест бандла сверяет копии с файлами установленного пакета и
пропускается, когда `share/lipi` недоступен.

## Оговорка <a id="caveat"></a>

Пакет не меняет ни lipi, ни правила проекта: проверки запускает установленная
команда, а правила живут в `AGENTS.md` и `.agents/lipi/`. Проект от бандла не
зависит — `lipi check` и `lipi new` работают и без DeepSeek Harness.
